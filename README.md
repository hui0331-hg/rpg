# 个人 RPG 系统

把你的日常，练成面板数值。日常化、定制化的个人成长游戏化面板 —— PWA，跑在 Android 主屏上，数据只存在本机。

当前进度：**M0 ~ M3 完成**（规则引擎 / 属性面板 / 任务面板 / 一句话记录 / 系统派发 / 7 日趋势 / 成就 / 长期记忆 / 周报）

---

## 一句话架构

```
你的一句话 / 点卡片
        ↓
  AI 只负责「理解」──→ { 做了什么活动, 多少量, 哪个任务 }   ← 绝不碰数值
        ↓
  结算引擎（确定性规则）──→ 递减 / 每日上限 / 连击 / 升级    ← 数值只在这里产生
        ↓
    面板 + 记录（可回放、可审计）
```

**为什么不让 AI 直接算数值**：同一个「跑了 5km」，模型今天给 +2、明天给 +5，面板几周就变成垃圾数据。养成类系统的全部价值在于数值可信，所以计算必须是确定性的。AI 只做它擅长的：理解自然语言、生成任务、写反馈文案。

## 数值系统

### 等级曲线

| 轨道 | 升到下一级所需 | 说明 |
|---|---|---|
| 主属性 | `60 × level^1.4` | Lv.1→2 需 60 点 |
| 技能 | `24 × level^1.3` | 成长更快 |
| 综合 | `120 × level^1.4` | 角色总经验 |

### 活动收益

经验池 = `基础系数 × 数量`，再按比例分配到主属性/技能。

标定基准对齐需求文档：**跑步 5km → 经验池 4 → 健康 +2、魅力 +2**（外加体能技能 +2.4）。

### 反作弊（中等强度）

| 机制 | 规则 |
|---|---|
| 同类递减 | 当天第 1/2/3/4/5 次 = 100%/60%/30%/10%/0% |
| 每日上限 | 活动经验池 40 点/天，任务奖励 30 点/天 |
| 单次上限 | 每种活动有独立上限（跑步 30km、学习 240 分钟…） |
| 连击加成 | 第 2 天起每天 +5%，封顶 +30%，断签重置 |

所有截断都会在结算反馈里说明原因，不静默吞掉。

## AI 解析（M1）

两种模式，自动切换：

| 条件 | 走什么 | 能力 |
|---|---|---|
| 已配置 Key / 代理 | DeepSeek（`deepseek-chat`） | 复杂表达、多事件、给任务 |
| 未配置 / 失败 | 本地关键词解析 | 常见说法：跑了5公里、背了20个单词、学习45分钟… |

配置入口：**档案 → AI 接入**。填 `baseUrl`、`model`、`API Key`，点「测试连接」。

### 关于 CORS（重要）

浏览器直接调用 LLM 接口可能被 CORS 挡住。若「测试连接」报 *网络请求被拒绝*，请二选一：

1. 先用本地解析（功能不受影响，只是理解能力弱一些）；
2. 部署一个转发代理，把 Key 放在服务端（更安全）。填到「代理地址」里即可。

`docs/ai-proxy-worker.js` 是一份可直接部署到 Cloudflare Workers 的转发实现（免费额度足够个人使用）。

### 安全边界

- AI 输出**一律当不可信数据校验**：未知活动类型直接丢弃、数量强制夹取、任务 id 必须真实存在；
- AI 永远不能输出属性数值；
- 请求只发送「当前这句话 + 待办任务标题 + 活动词表」，不含历史记录、个人档案；
- Key 只存在本机浏览器 IndexedDB，不上传。

## 任务派发（M2）

「任务」页顶部可以点「给我安排今天的事」。派发不是随机抽，而是先算清楚四件事，再打分排序：

| 打分信号 | 作用 |
|---|---|
| 可用时间 | 只有 10 分钟就绝不推 60 分钟的任务（硬约束） |
| 能力短板 | 近 7 天涨得最慢的主属性优先补 |
| 今日同类 | 今天已经运动过，就少推运动类（收益本来就被递减） |
| 完成率 | 近 7 天完成率低于 35% 时会自动降难度，先找回节奏 |
| 目标对齐 | 命中「减脂 / 过六级」这类目标的任务加分 |
| 拒绝记忆 | 你拒绝或换掉的任务不会反复回来烦你 |
| 时段 | 早上推运动类、深夜不推力量训练 |
| 额度余量 | 今日经验快满了就不推重任务 |

**AI 在这里做什么**：只在这个候选池里挑一个、改写标题、润色理由。
候选池外的东西一律拒绝；AI 挑的任务耗时超出你可用的时间会被打回去。
奖励仍然由 `分类 + 难度` 查表得到 —— **AI 碰不到数值**。

「换一个」会累积排除项，「不要」会记录拒绝，两者都会影响后续推荐。

## 长期记忆 · 成就 · 周报（M3）

### 为什么记忆必须「算出来」

把一年日志塞进 prompt 不现实（贵、慢、还会被截断）。让模型自己「记住你」更糟——它会编。

所以做法是每次请求前，从存档里算出几行**可复算的事实**再喂给它：

```
- 已记录 38 天 / 共 112 条；当前连击 6 天
- 本周：经验 46，活跃 5/7 天；属性增长 智慧+8.4 健康+6 意志+2 魅力+0
- 稳定习惯：跑步、背单词
- 近 30 天常做：跑步(9次)、背单词(7次)、阅读(3次)
- 明显停滞（10 天无增长）：魅力
- 用户目标：减重 5 公斤；一个月后过英语六级
```

这段摘要同时进入**意图解析**和**任务派发**的 prompt。好处是：AI 能说「你魅力已经两周没动了」，
但这句话的依据来自数据，不是它猜的。「周报」页里也能直接看到这段摘要。

### 成就

16 个成就，全部**从存档复算**：

- 存档里只存「什么时候解锁的」，不存「我判定你完成了」；
- 达成条件写在 `data/achievements.ts` 的 `value(ctx) >= target` 里，可以随时核对；
- 结算后自动检查，新解锁会出现在结算弹层里；
- 每一条都能打开历史记录复算出来。

覆盖：首次记录 / 首个任务 / 连击 3·7·30 天 / 经验 100·1000 / 综合 Lv.5 /
跑步 20·100km / 单词 500 / 学习 600 分钟 / 四属性全 Lv.3·5 / 完成 10 任务 / 早睡 10 次。

### 周报

顶栏新增「周报」页，滚动最近 7 天：

- 数字：经验池、活跃天数、最高单日、任务完成数、最常做的活动、属性增长条；
- **建议是规则算的**（不是 AI 编的），优先级：先看有没有记录 → 再看活跃天数 → 再看完成率 → 最后看哪项属性停滞；
- 一键复制 Markdown，方便贴到别处存档。

## 部署到 GitHub Pages

1. 推到 GitHub 仓库；
2. Settings → Pages → Source 选 **GitHub Actions**，或直接用任意静态托管；
3. `vite.config.ts` 里 `base: './'` 已配好相对路径，放在 `/<repo>/` 子路径下也能正常工作。

```bash
pnpm build
# 把 dist/ 整个目录推到你选择的静态托管即可
```

> PWA 的「安装到主屏幕 + 离线可用」要求 **HTTPS** 安全上下文。
> 局域网 `http://192.168.x.x` 只能当普通网页用，装不成 App。

## 已知限制

- 存档只在当前浏览器本地，跨设备需手动导出/导入 JSON；
- 本地解析只认常见句式，复杂表达识别不了会提示改写；
- 派发模板目前是固定 17 个，重复用久了会觉得眼熟，后续应支持自定义模板；
- 成就达成线是拍脑袋定的（如「跑步 100km」），真实用几个月后应重新校准；
- 周报是滚动 7 天，不是自然周（周一~周日）；
- AI 润色周报/日文尚未实现，目前只有规则生成的版本；
- 面板数值尚未做长期膨胀回归（需要真实数据跑几周再调 `balance.ts`）；
- 渲染测试只覆盖首帧，交互流程仍需人工点一遍。
